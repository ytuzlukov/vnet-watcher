# vnet-watcher

Лёгкий Java-сервис, который раз в 5 минут проверяет доступность:

- `https://valut.net`
- `https://app.valut.net`
- `https://pro.valut.net`
- `https://docs.valut.net`
- `https://app.travel.cards`

Проверка считается успешной, только если после HTTPS-редиректов получен ответ
`HTTP 200`. Ошибками считаются остальные HTTP-коды, таймауты, ошибки DNS,
подключения и TLS.

После трёх ошибок подряд бот отправляет в Telegram отдельный алерт для
проблемного сайта. Повторных сообщений во время того же сбоя нет. Сообщение
о восстановлении отправляется только в том случае, если до него был отправлен
алерт о сбое.

## Настройка Telegram

1. Добавьте бота администратором приватного канала с правом публикации сообщений.
2. Скопируйте `.env.example` в `.env`.
3. Укажите в `.env`:

   - `TELEGRAM_BOT_TOKEN` — токен от BotFather;
   - `TELEGRAM_CHAT_ID` — числовой идентификатор канала вида `-100...`.

Файл `.env` исключён из Git и не должен попадать в репозиторий. Для деплоя
через GitHub Actions храните значения в GitHub Actions Secrets, а на Timeweb
передавайте их контейнеру как переменные окружения.

## Запуск в Docker

```shell
docker compose up -d --build
```

Посмотреть работу сервиса:

```shell
docker compose logs -f
```

Остановить:

```shell
docker compose down
```

## Переменные окружения

| Переменная | Обязательна | Значение по умолчанию |
|---|---:|---|
| `TELEGRAM_BOT_TOKEN` | да | — |
| `TELEGRAM_CHAT_ID` | да | — |
| `MONITORED_URLS` | нет | пять адресов выше |
| `CHECK_INTERVAL_SECONDS` | нет | `300` |
| `FAILURE_THRESHOLD` | нет | `3` |
| `CONNECT_TIMEOUT_SECONDS` | нет | `10` |
| `REQUEST_TIMEOUT_SECONDS` | нет | `20` |

`MONITORED_URLS` принимает HTTPS-адреса через запятую.

## Локальная проверка

Требуются JDK 21 и Maven:

```shell
mvn clean test
mvn package
```

Состояние сайтов хранится только в памяти. После перезапуска контейнера
счётчики неудачных проверок начинаются заново.
